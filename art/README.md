# แนวทางภาพประกอบ (Art Direction)

> **สถานะ: style v0.1 ตรึงแล้ว (2569-10-28)** — [`style.json`](style.json), ภาพตัวอย่างที่ [`approved/`](approved/manifest.json), บันทึกรอบทดสอบที่ [`rounds/`](rounds/)
> เอกสารนี้คือ ROADMAP เฟส 5 (Visual bible)

## 1. หลักการ

1. **"อะไร" มาจากหลักฐาน, "ดูอย่างไร" มาจากสไตล์** — เครื่องแต่งกาย ทรงผม ข้าวของ ดึงจาก `lore/` เสมอ ห้ามให้โมเดลเดาเอง
2. **ความคงที่มาจากการตรึง 3 อย่างพร้อมกัน** — ข้อความ (style block) + เครื่องมือ (โมเดล/เวอร์ชัน/พารามิเตอร์) + ภาพตัวอย่างที่อนุมัติแล้ว
3. **สิทธิ์ต้องสะอาด** — ภาพที่ป้อนเข้าเครื่องมือต้องมี `genUse` อนุญาต (ข้อ 5)
4. **ภาพสะท้อนระบบเกม** — แผลเป็น ความพิการ อายุ ชนชั้น จากเซฟต้องปรากฏในภาพ

## 2. สองสไตล์: ความจริง กับ ตำนาน

| | **Reality** — ชีวิตจริง | **Chronicle** — ตำนาน/พงศาวดาร |
|---|---|---|
| ใช้กับ | portrait, event, ฉากประจำวัน, แผลเป็น | ตำนานตระกูล (`Legend.current`), บันทึกพงศาวดาร |
| แนวทาง (ร่าง) | ภาพประกอบกึ่งสมจริง เช่น สีน้ำ/หมึกผสมสี โทนดิน | จิตรกรรมไทยประเพณี พื้นแดง สีแบน ตัดเส้น ไม่มีทัศนียภาพแบบตะวันตก |
| อ้างอิงสไตล์ | ยังไม่กำหนด | `attire.wat_ko_kaeo_reference` (พ.ศ. 2277) |
| prompt ประกอบจาก | `Legend.truth` / สถานะจริงของตัวละคร | `Legend.current` (ฉบับที่ถูกบิดเบือน) |

ตัวอย่าง: ปู่ผ่าฟักทองในครัว → ภาพ Reality เป็นเด็กนิ้วเลือดออกในลานครัว
ฉบับที่เล่ากันสามรุ่นต่อมา → ภาพ Chronicle เป็นนักรบฟันข้าศึกกลางสนามรบ — ผู้เล่น "เห็น" ความบิดเบือน

## 3. โครง prompt แบบชั้น

| ชั้น | ที่มา | ตรึงไหม |
|---|---|---|
| `STYLE` | `art/style.json` (Reality หรือ Chronicle) | ✅ ตรึงเป็นเวอร์ชัน |
| `SUBJECT` | `visualDescriptor` ใน `lore/entries/attire.json` ฯลฯ ตามยุค/ชนชั้น/เพศ | สร้างอัตโนมัติ |
| `STATE` | ตัวละครในเซฟ: อายุ, แผลเป็น (`BodyPart.scars`), อวัยวะที่เสีย, ชนชั้น | สร้างอัตโนมัติ |
| `SCENE` | tag ของ event (`place:kitchen`, `situation:feast`) → `material`/`place` ใน lore | สร้างอัตโนมัติ |
| `NEGATIVE` | `art/style.json` + คำผิดยุคจาก lore | ✅ ตรึง |

prompt ที่ประกอบแล้วต้องแนบ **รายการอ้างอิง** ว่าแต่ละท่อนมาจาก lore id ไหน (ตรวจย้อนได้)

### 4.3 รอบทดลอง
แต่ละรอบบันทึกใน `art/rounds/<round-id>.json`: style block ที่ลอง, เครื่องมือ/เวอร์ชัน/พารามิเตอร์, ภาพผลลัพธ์, คะแนน, ข้อสังเกต

เกณฑ์ให้คะแนน (1–5):
- **ตรงหลักฐาน** — ไม่มีของผิดยุค (ตรวจกับ lore)
- **คงที่** — 10 โจทย์ดูเป็นเกมเดียวกัน, ตัวละครเดียวกันสร้างซ้ำแล้วจำได้
- **อ่านง่ายที่ขนาดเล็ก** — portrait ใน UI ราว 128 px ยังเห็นชนชั้นและแผลเป็น
- **ความรู้สึก** — ตรงธีม (ชีวิตธรรมดาที่มีรายละเอียด ไม่ใช่ภาพโฆษณาท่องเที่ยว)

### 4.4 ตรึงเป็น v1 — ✅ ตรึง v0.1 แล้ว (ผ่าน 9/10 โจทย์; ข้อจำกัดของเครื่องมืออยู่ใน `style.json` › `knownLimitations`)
เก็บใน `art/style.json`:
- style block, negative prompt
- เครื่องมือ + เวอร์ชัน + พารามิเตอร์ (อัตราส่วน, guidance, sampler, นโยบาย seed)
- ภาพที่อนุมัติ → `art/approved/` พร้อม manifest (prompt เต็ม, พารามิเตอร์, เวอร์ชัน, วันที่) — ใช้เป็น style reference ต่อ และเป็นข้อมูลเทรน LoRA ภายหลังถ้าเงื่อนไขบริการอนุญาต

## 5. การใช้ภาพอ้างอิง

### 5.1 ระดับการใช้ (`genUse` — จะเพิ่มใน `Source`)

| ค่า | ความหมาย | ตัวอย่าง |
|---|---|---|
| `none` | ห้ามใช้ทุกทาง นอกจากอ่านเพื่อค้นคว้า | ภาพในบทความ SPAFA, ภาพไตรภูมิ Berlin |
| `reference-only` | คน/AI ดูแล้วจดเป็นข้อเท็จจริง (visual study) ได้ ห้ามป้อนเข้าเครื่องมือสร้างภาพ | ภาพที่ license ไม่ชัด |
| `input-ok` | ป้อนเป็นภาพอ้างอิงได้ (ต้องทำตามเงื่อนไข เช่น ให้เครดิต) | ภาพ CC BY, ภาพสมบัติสาธารณะ |
| `training-ok` | ใช้เทรนได้ | ภาพที่ถ่ายเอง, ภาพที่จ้างวาดพร้อมสิทธิ์, ภาพที่เราสร้างแล้วอนุมัติ |

ระวัง: CC BY-SA อาจบังคับให้ภาพที่ได้ต้องเผยแพร่แบบเดียวกัน — ไม่เหมาะกับ asset เชิงพาณิชย์ ให้ใช้แค่ `reference-only`

### 5.2 Visual study (ตีความภาพเป็นข้อเท็จจริง)
ดูภาพจริงแล้วจดเป็นรายการใน lore แบบมีโครงสร้าง: แหล่ง + ตำแหน่งในภาพ, ชนชั้น/เพศ, เครื่องนุ่งห่ม, สี, ทรงผม, เครื่องประดับ, ฉาก, ท่าทาง, ชิ้นส่วน prompt
- จดเป็น **องค์ประกอบทั่วไป** ไม่บรรยายภาพเดียวละเอียดทีละจุดเพื่อให้วาดซ้ำ
- **ไม่จดลักษณะใบหน้า** ของบุคคลในภาพถ่าย
- AI ช่วยอ่านภาพได้ แต่ต้องมีคนตรวจก่อน `verified: true`

### 5.3 ภาพถ่ายยุคหลัง (ราว พ.ศ. 2400 เป็นต้นไป)
ห่างจาก slice ราว 100 ปี → ใช้เป็น **กายภาพ** เท่านั้น (`appliesAs: physicality`):
- ✅ ผ้าทิ้งตัวอย่างไร, ผิว รูปร่าง ท่านั่ง/หมอบ, เนื้อวัสดุ ไม้ไผ่ เรือ ภาชนะ
- ❌ ชนิดเครื่องแต่งกาย ทรงผม เสื้อขุนนางของ slice — ยกเว้น lore ยืนยันว่าเหมือนเดิม
- ✅ **ข้อยกเว้น: ทรงผมเด็ก** (ตัดสินใจ 2569-10-28) — ใช้ภาพถ่ายยุค ร.4–ร.5 เป็นต้นแบบได้ เพราะทรงผมเด็กผูกกับพิธี (ทำขวัญเดือนโกนผมไว้จุก → โกนจุกอายุ 11 หรือ 13 ทั้งชายหญิง; ดู `ritual.month_old_tham_khwan`, `ritual.topknot_cutting`) ซึ่งเปลี่ยนช้ากว่าแฟชั่นมาก — บันทึกเป็น visual study แบบ `appliesAs: pattern` พร้อม projection

แหล่งที่น่าสนใจ: ภาพ John Thomson (ถ่ายในสยามราว พ.ศ. 2408, Wellcome Collection — ตรวจ license รายภาพ), ภาพฟรานซิส จิต, หอจดหมายเหตุแห่งชาติ (เงื่อนไขการใช้ของคลังเอง)

## 6. ข้อห้ามและความอ่อนไหว

- **พระมหากษัตริย์และเจ้านาย** — ไม่สร้างภาพ ไม่ใช้พระบรมฉายาลักษณ์เป็น ref
- **พุทธรูปและภาพศักดิ์สิทธิ์** — ไม่ดัดแปลงเป็นตัวละครหรือฉากตลก
- **บุคคลจริงที่ระบุตัวได้** — ห้ามสร้างภาพให้หน้าเหมือนคนในภาพถ่ายเก่า
- **ความเปลือยตามหลักฐาน** — lore บันทึกว่าหญิงสามัญไม่มีผ้าคลุมอก และเด็กไม่นุ่งผ้าจนราว 4–5 ขวบ
  - **เด็ก: ไม่ใส่เสื้อได้ แต่ท่อนล่างต้องมีผ้านุ่งเสมอ และต้องเห็นชัดในภาพ** — ภาพเด็กชนบทเปลือยท่อนบนเป็นเรื่องปกติและไม่เชิงเพศ ส่วนที่ต่างจากหลักฐาน (เด็กเล็กไม่นุ่งผ้าจนราว 4–5 ขวบ) บันทึกเป็นการตัดสินใจเชิงศิลป์ (`invented`) ถ้าท่อนล่างถูกบังจนไม่แน่ใจ ให้ถือว่าภาพไม่ผ่าน
  - ผู้ใหญ่: **ยึดหลักฐาน แต่ใช้การจัดภาพเป็นหลัก** (ตัดสินใจ 2569-10-28)
    - ลำดับที่ใช้: (1) portrait ครอปศีรษะถึงไหล่ → (2) มุมหลัง/ด้านข้าง/ระยะไกล/มีของบังตามธรรมชาติ → (3) ภาพหมู่ที่คนตัวเล็ก
    - ไม่ใส่ผ้าคลุมให้ผิดหลักฐาน (หญิงสามัญไม่มีผ้าห่มพาดอก, ผู้มีฐานะมี) — ถ้าเครื่องมือใส่ให้เอง ถือเป็นภาพที่ไม่ผ่านเกณฑ์ "ตรงหลักฐาน"
    - **ไม่ออกแบบภาพหรือ UI ที่ต้องพึ่งภาพเปลือยด้านหน้า** — รอบ 00 Gemini ยอมสร้าง D2 แต่ผลไม่คงที่และนโยบายอาจเปลี่ยน
    - ห้ามเน้นเชิงเพศในทุกกรณี; บันทึกการตัดสินใจนี้เป็น `invented` (การนำเสนอ) ไม่ใช่ข้อเท็จจริง
- **ภาพเหมารวมชาวต่างชาติ** — จิตรกรรมยุคนั้นวาดชาวต่างชาติเป็นผู้ร้าย ใช้เป็นสไตล์ Chronicle ได้ แต่อย่ายกไปเป็นภาพ Reality

## 7. การใช้ภาพในเกม: คลังภาพสร้างล่วงหน้า (ตัดสินใจ 2569-10-28)

เกมรันในเบราว์เซอร์แบบ static ไม่มี server → **ไม่สร้างภาพระหว่างเล่น** ใช้คลังภาพที่ผลิตไว้ล่วงหน้า แล้วเกมเลือกภาพด้วย tag
เป้าหมายคือภาพ "ประกอบเกมได้ลื่นไหล" ไม่ใช่เกมที่ต้องนั่งเล่น prompt เพื่อดูภาพ

### 7.1 ภาพบอกอะไร / ตัวหนังสือบอกอะไร

| ภาพ | ตัวหนังสือ/สถานะ |
|---|---|
| ชนชั้น เพศ วัย ยุค | แผลเป็นข้างไหน นิ้วไหน, ความพิการเฉพาะจุด |
| ฉาก บรรยากาศ อารมณ์ | ชื่อ ปมในใจ ข้อห้ามตระกูล |
| ความจริง ↔ ตำนาน (Reality / Chronicle) | รายละเอียดที่ตำนานบิดเบือน |

**กฎ:** ภาพหนึ่งภาพต้องใช้ซ้ำได้หลายสถานการณ์ — รายละเอียดที่สำคัญกับสถานะของคนเดียวอยู่ในตัวหนังสือ
ยกเว้นเดียว: **แผลบนใบหน้า** (มีผลทางสังคมในระบบเกม) ทำเป็นแบบ "มีแผลบนหน้า" ทั่วไป ไม่ระบุตำแหน่ง

### 7.2 ชุดภาพ

| ชนิด | แบ่งตาม | ประมาณ |
|---|---|---|
| Portrait | ชุดหน้าตา × เพศ × วัย × เครื่องแต่งกาย (ดู 7.3) | ~160 |
| ฉากประจำ | ครัวลานบ้าน, เรือน, ท่าน้ำ/ตลาด, วัด, ในวัง, ทุ่งนา, สนามรบ | 10–15 |
| ภาพ event | หนึ่งภาพต่อ event สร้างพร้อมตอนเขียน event | ตาม event |
| ภาพตำนาน (Chronicle) | ตามชนิดเรื่อง: ศึก, ลาง/นิมิต, ผีคุ้มครอง, วีรกรรมในวัง | 6–10 |
| เหตุการณ์ประวัติศาสตร์ | เสียกรุง, ผลัดแผ่นดิน | 2–4 |

เสิร์ฟเป็น WebP กว้าง ~1024 px (ภาพละ ~80–150 KB) จาก CDN โหลดเมื่อจะแสดง

### 7.3 หน้าตาประจำสายตระกูล + ยีน

- **ไม่ทำตัวละครแบบแยกชิ้นส่วน (paper-doll)** — ภาพจาก AI ทำชิ้นส่วนให้ตรงตำแหน่ง/แสง/ลายเส้นกันไม่ได้; ต้องใช้ศิลปินหรือ pipeline ล็อกท่า ซึ่งเกินขอบเขตตอนนี้
- **ชุดหน้าตา (face family) 8–12 แบบ** แต่ละแบบมีครบ 4 วัย (เด็กไว้จุก / หนุ่มสาว / ผู้ใหญ่ / ชรา) × 2 เพศ — ทำวัยต่อไปด้วยการแก้ภาพ "คนเดิมแต่แก่ขึ้น" เพื่อให้จำหน้าได้
- **เครื่องแต่งกายบอกชนชั้น** 2 แบบ (สามัญ / มีฐานะ) + ขุนนาง (ลอมพอก) และพระ เฉพาะวัยผู้ใหญ่–ชรา
- **ยีนเลือกชุดหน้าตา:** ลูกได้ชุดหน้าตาจากฝั่งพ่อหรือแม่ → ผู้เล่นเห็นเองว่า "หลานหน้าเหมือนตา"; ตัวละครใช้ชุดเดิมทั้งชีวิต
- **หน้าคล้ายกันทั้งผังตระกูลไม่เป็นปัญหา** — ความหลากหลายในผังตระกูลมาจากวัยที่ตายและฐานะในวาระสุดท้าย (เครื่องแต่งกาย/ลอมพอก/จีวร) ซึ่งแสดงคู่กับภาพอยู่แล้ว
- **ห้ามผูกสีผิวกับชนชั้น** — สีผิวเป็นยีนที่สุ่มอิสระจากชนชั้น ชนชั้นบอกด้วยเครื่องแต่งกายเท่านั้น
- ⚠️ **ยังไม่ทดสอบ:** Gemini ทำคนเดิมให้แก่ขึ้นแล้วยังจำหน้าได้ไหม → **รอบ 03** (หน้า 2 แบบ × 4 วัย) ต้องผ่านก่อนผลิตจริง

### 7.4 เกมเลือกภาพ

- ภาพแต่ละภาพมี tag (`estate:*`, `sex:*`, `age:*`, `face:*`, `place:*`, `story:*`) → ให้คะแนนตาม tag ที่ตรงกับสถานการณ์ เลือกคะแนนสูงสุด ไม่มีที่ตรงถอยไปภาพทั่วไป
- ภาพตำนานเลือกตามชนิดเรื่อง ส่วนรายละเอียดที่บิดเบือนเล่าด้วยตัวหนังสือ

### 7.5 ขั้นตอนผลิต (offline)

1. `art/assets.spec.json` — รายการภาพที่ต้องมีพร้อม tag
2. `npm run art:prompts` — ประกอบ prompt ทุกภาพจาก `style.json` + lore (prompt builder ไม่ต้องรู้จักตัวละครรายตัว)
3. สร้างใน Gemini ภาพละ 2 ครั้งแล้วคัด (รับมือ `knownLimitations` ไปในตัว)
4. `npm run art:ingest` — ย่อ แปลง WebP ตรวจชื่อ เขียน manifest ที่เกมโหลด
5. ก่อนปล่อยเกม: ตรวจเงื่อนไขการใช้ภาพที่สร้างด้วย Gemini เชิงพาณิชย์

## 8. ไฟล์ที่จะมี

```
art/
  README.md            เอกสารนี้
  style.json           style block ที่ตรึงแล้ว (Reality, Chronicle) + เวอร์ชัน
  assets.spec.json     รายการภาพที่ต้องผลิต + tag (ข้อ 7.5)
  rounds/              บันทึกรอบทดลอง (ภาพไม่ขึ้น git)
  approved/            ภาพตัวอย่างสไตล์ที่อนุมัติ + manifest
public/art/            ภาพที่เกมใช้จริง (WebP) + manifest
src/art/               สคริปต์ art:prompts / art:ingest และตัวเลือกภาพตาม tag
```
