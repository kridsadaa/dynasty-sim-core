## 2. ข้อเสนอ

### ก. คำใบ้บอกการได้วิชา (ทำก่อน)
- ผู้เล่นได้วิชา → "ได้ฝึก{ชื่อวิชา}"; คนอื่นใน role ได้วิชา → "{ลูก}ได้ฝึก{ชื่อวิชา}"
- ไม่บอกตัวเลข (แนวเดียวกับความโปรดปราน — ตัวละครรู้แค่ว่าได้ฝึก)

### ข. ปรับ 4 event ที่เจอบ่อย
1. **วันพระ** (lore `ritual.holy_days_1680s`: งดหาปลา เอาเงิน/ผลไม้/ผ้าไปถวายวัด)
   - "พาลูกไปวัด" เสียค่าของถวาย 0.3 ตำลึงเท่ากับ "ไปวัด" (ไปวัดเหมือนกัน)
   - "แอบหาปลา" ได้ปลาไปขาย +0.3 ตำลึง (เงิน vs บาป เป็นข้อแลกเปลี่ยนจริง)
   - "ถือศีล" หนักใจเพิ่มจาก 0.02 → 0.04 (หิว) ยังได้บุญมากสุดโดยไม่เสียเงิน
2. **ลอยโคม** (lore `ritual.floating_lanterns_1680s`: โคมใหญ่เล็กตามแรงศรัทธา)
   - "พาลูกไปลอยโคม" เสียค่ากระดาษ 0.3 ตำลึง
3. **รดน้ำผู้ใหญ่** (lore `ritual.fifth_month_bathing_1680s`: ชาวบ้านไปสรงน้ำพระที่วัดด้วย)
   - เพิ่มตัวเลือก "ไปสรงน้ำพระที่วัดก่อน แล้วกลับมารดน้ำ{parent}" — ค่าน้ำหอม 0.3 ตำลึง ได้บุญ 1 สนิทขึ้นเท่า "รดอย่างตั้งใจ"
   - "รดอย่างตั้งใจ" ไม่ได้บุญแล้ว (บุญย้ายไปอยู่ที่วัด) เหลือแค่สนิทขึ้น
4. **ซ้อมมวย**: "แลกหมัด" วิชา 4 → 5, "รำดาบ" วิชา 3 → 2 (เสี่ยงแล้วได้มากกว่าชัด)

### ค. ตัวตรวจใน `sim:check`
- event ที่ผู้เล่นเจอ ≥ 1%: ไม่มีตัวเลือกไหนที่ "แพ้ขาด" อีกตัวเลือก (อีกตัวดีกว่าหรือเท่ากันทุกด้าน และดีกว่าอย่างน้อยหนึ่งด้าน)
- นับเฉพาะผลที่ตัวเลข: เงิน บุญ หนักใจ วิชา ความโปรดปราน หน้าตาตระกูล ความเสี่ยง; ตัวเลือก "ไม่ทำอะไร" (ไม่มีผล) ยกเว้น
- event ที่ตั้งใจให้มีตัวเลือกชนะขาด ใส่รายการยกเว้นพร้อมเหตุผล

### ง. ไม่ทำรอบนี้
- ต้นทุนเวลา/แรงงานในเรือน (PLAN บอกค้าง) — ต้องมีระบบใหม่; ใช้ เงิน/หนักใจ/ความโปรดปราน ที่มีอยู่ไปก่อน
- ตั้งชื่อลูก — รอ lore ตามเดิม
- `outing.lotus_m` — เจอน้อย (1.3%) ไว้รอบหน้า
- `family.death_bad` (0.9–1%) "เผาทันที" แพ้ "ฝังก่อน" ทุกด้าน — เป็นตัวเลือกผิดธรรมเนียมที่ตั้งใจให้แย่ ใส่ในรายการยกเว้นของตัวตรวจไว้ก่อน ถ้าจะให้มีอะไรได้ (เช่น ไม่ต้องเสียค่าทำศพสองหน) ต้องหา lore ก่อน

## 5. ผลหลังทำ (2026-11-05)
- คำใบ้: "ได้ฝึก{วิชา}" ขึ้นก่อนผลอื่น, ของคนอื่นเป็น "{ชื่อ}ได้ฝึก{วิชา}"; งานบุญ/ผูกมิตร/ศึก บอก "ได้เงิน X ตำลึง" ด้วย (เดิมบอกแค่เสียเงิน) — ทดสอบใน `sim:check` ข้อ [5h3]
- ตัวตรวจ [5h3b]: event ที่เจอ ≥ 1% (19–24 ชนิดแล้วแต่จำนวน seed) ไม่มีตัวเลือกแพ้ขาด; ยกเว้น `family.death_bad`
- **ข้อจำกัดของตัวตรวจ:** จับได้เฉพาะ "แพ้ทุกด้าน" จริงๆ — ลองรันกับข้อมูลก่อนแก้ก็ผ่าน เพราะปัญหาของ 4 event เดิมคือ "คุ้มกว่ากันมาก" ไม่ใช่แพ้ทุกด้าน (เช่น ไปวัดเองได้วิชานิดหน่อยที่พาลูกไปไม่ได้) ตัวตรวจนี้จึงกันแค่กรณีร้ายแรงในเนื้อหาใหม่ ส่วนความคุ้มต้องดูด้วยตาหรือวัดด้วย `sim:policy`
- ตอนเขียนตัวตรวจพบว่าเงินที่คิดตามศักดินา (`perSakdina`) ต้องนับด้วย ไม่งั้น "ยอมเสียค่าปรับ" กับ "รับของกำนัล" ดูเหมือนแพ้ขาด

## 7. รอบ 3 (2026-11-05)
- `family.death_bad` "ฝังไว้ก่อน" เสีย 2 ตำลึง (ตัวเลขของเกม) เป็นค่าขุดเผาและทำบุญภายหลัง — อนุมานจาก lore `belief.bad_death_burial` (ตายร้ายฝังก่อนแล้วขุดเผาภายหลัง) และ `ritual.funeral_cremation` (งานเผาศพภายหลังแพงมาก ครอบครัวขายที่ดินหรือเลื่อนงานเพราะค่าใช้จ่าย) — "เผาเลย" จึงถูกกว่าแต่เสียหน้าและใจหนักกว่า ไม่ต้องยกเว้นในตัวตรวจอีก
