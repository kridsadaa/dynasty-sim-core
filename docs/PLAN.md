## ทำตอนนี้

### 1. P0 — ผู้เล่นตายราวอายุ 29 โดยไม่มีทางเลือก
ผู้เล่นรู้สึกว่า "ถูกบังคับให้ตายตอน 30" · เสร็จเมื่อ: ตายก่อน 30 ลดลงต่ำกว่าเพดานใหม่ใน `sim:check` และผู้เล่นมีทางเลือก (สู้/หนี/พาใครไป) ก่อนเสียกรุง
ส่วนที่ทำแล้ว: modal แจ้งการตาย, badge สภาวะบ้านเมือง — ที่เหลือคือข่าวเตือนล่วงหน้า, event สู้หรือหนี, เลือกพาใครหนี

- [ ] **ผู้เล่นตายช่วงอายุ ~29 เพราะเสียกรุง 2310 โดยไม่มีทางเลือก (พบ 2026-11-02)** — จำลอง 60 seed: ผู้เล่นรุ่นแรกตายอายุ 25–29 ราว 18% (11/60 จากเสียกรุง, 2 จากข้าวยาก) เพราะเริ่มเกมปี 2288 อายุ 7 จึงอายุ ~29 พอดีตอน 2310 และ `deathRisk` 0.15 (+ข้าวยาก 0.06/0.04) ใน `rules.json` ใช้กับผู้เล่นเหมือนคนอื่น ทั้งที่ผู้เล่นไม่ได้เลือกอะไรเลย ผู้เล่นรู้สึกว่า "ถูกบังคับให้ตายตอน 30" ข้อเสนอที่ตกลงกันไว้ (ยังไม่ทำ):
  - **เรื่องเตือนล่วงหน้า** — ข่าวแว่วจากในกรม/ข่าวลือก่อน แล้วค่อยแรงขึ้นเป็นระยะ ต้องดูบริบทประวัติศาสตร์ว่าข่าวศึกพม่าปี 2310 มาถึงล่วงหน้าได้เร็วแค่ไหน (ถ้ากระชั้นชิด การหนีเสี่ยงมาก) ปัจจุบันเกมไม่มี modal แจ้งว่าจะมีสงคราม
  - **event ตัดสินใจ ปักหลักสู้ หรือ หนี** — ผู้เล่นที่ฝีมือ/สกิลสูงสู้ปกป้องบ้านได้ สกิลสูงหนีรอดได้ ผลลัพธ์ผูกกับสเตตัสผู้เล่น ไม่ใช่ทอยลอยๆ
  - **เลือกว่าจะพาใครหนี** — ยกครัว / พาแค่ลูก / ไปคนเดียว ยิ่งพาคนมากและขนทรัพย์มาก ยิ่งเสี่ยง ยกเว้นเตรียมหนีแต่เนิ่นๆ (เชื่อมกับระบบทรัพย์สิน: ทองฝังดินรอด ของที่ไม่ได้ซ่อนเสียหาย ดู `applyHistoricalShocks` ใน handover.ts) ต้องออกแบบว่าจัดการทรัพย์สมบัติอย่างไร
  - ~~**หน้าต่างแจ้งการตายของผู้เล่น**~~ — ทำแล้ว (2026-11-02): push `playerDied` → modal บอกสาเหตุ (`deathCause`) อายุ และผู้สืบ เวลาหยุดจนกดรับทราบ แล้วไปหน้าเลือกทายาท (ทดสอบในเบราว์เซอร์แล้วเฉพาะกรณีมีผู้สืบหลายคน; กรณีผู้สืบคนเดียวและสิ้นสายผ่าน typecheck/sim:check แต่ยังไม่ได้ดูในเบราว์เซอร์)
  - **ทุก event ใหญ่ควรบอกว่าเป็น event อะไรและมีผลอย่างไร** — ทำแล้วบางส่วน: badge "บ้านเมืองตอนนี้" บนแผงตัวละคร (`eraConditions` ใน views.ts, คำนวณจาก `history` + `lasts` ไม่เก็บใน state, ยังไม่ได้ดูในเบราว์เซอร์เพราะต้องเล่นถึงปี 2310) ยังขาด: modal แจ้งตอน event เริ่ม และคำอธิบายว่ามีผลอย่างไร (ของแพง ฯลฯ — ตอนนี้ไม่มีกลไกราคา)

### 2. ผูกทักษะกับความก้าวหน้า และทำให้ผลมองเห็นได้
ผู้เล่นฝึกวิชาแล้วต้องเห็นว่าขึ้นยศเร็วขึ้น · เสร็จเมื่อ: หน้าเลื่อนยศ/ตัวเลือกแสดงตัวช่วยจากทักษะ (+Y%) และ `sim:check` ยังอยู่ในช่วงสมดุล

- [ ] **ผูกการเลื่อนยศ/ความก้าวหน้ากับทักษะและมรดกตระกูล (เสนอ 2026-11-02)** — ตอนนี้การเลื่อนยศใน `career.ts` ขึ้นกับ `favor` + จำนวนปีในตำแหน่งเท่านั้น; ทักษะมีผลแค่เป็นเงื่อนไขขั้นต่ำตอนเข้ากรม (`requires` skill) และ perk/มรดกบางตัวคูณ `favor` 15–25% → ผู้เล่นฝึกวิชาแล้วไม่เห็นว่าขึ้นยศเร็วขึ้น ทางแก้: ให้ทักษะที่เกี่ยวกับกรม/สายนั้นและระดับมรดกตระกูลมีผลต่อ `favor` ที่ต้องใช้เลื่อนยศหรือโอกาสว่าง/คัดเลือกโดยตรง; โครงเดียวกันใช้กับสายอาชีพอื่นในอนาคต (ทักษะ → โอกาสก้าวหน้า); ตัวเลขเป็นของเกม ต้องวัดสมดุลด้วย `sim:check` (ผู้เล่นมีตำแหน่งหลัง 2370 วัดได้ราว 28–33% ช่วงที่ยอมรับ 15–60%) ทำคู่กับข้อ "แนวการเล่นแต่ละยุคยังไม่ต่างกัน" ด้านบนและหลอดยุคสมัยใน UI เพราะให้เป้าหมายระยะยาวที่เห็นความคืบหน้า
- [ ] **ทำให้ผลของทักษะและตัวเลือกมองเห็นได้ (เสนอ 2026-11-02)** — ผู้ทำเกมสัมผัสผลของทักษะได้เพราะรู้ระบบ ผู้เล่นปกติอาจไม่รู้ว่าทักษะมีผล ทางแก้: หน้าเลื่อนยศ/ตัวเลือกบอกว่า "ทักษะ X ช่วยเพิ่มโอกาส +Y%" ใช้โครง `OddsFactorView` ของระบบ `intent` ซ้ำได้; ต้องให้คนนอกทีมลองเล่นเพื่อยืนยันว่าผู้เล่นสังเกตเห็นจริง (ยังไม่เคยทดสอบ)

### 3. ข้อแลกเปลี่ยน "ได้อย่างเสียอย่าง" ใน event
เสร็จเมื่อ: event ที่เจอบ่อยที่สุดมีตัวเลือกที่ได้-เสียชัดเจนอย่างน้อยหนึ่งคู่

- [ ] **event ส่วนใหญ่ยังไม่มีข้อแลกเปลี่ยน "ได้อย่างเสียอย่าง" ที่จับต้องได้ (เสนอ 2026-11-02)** — นับจากโครงสร้างข้อมูล: 71 event 201 ตัวเลือก มีแค่ 8 ตัวที่ไม่มี effect เลย แต่ผลส่วนใหญ่เป็นของเบา มองไม่เห็น (bond/relation 63 ครั้งต่อชนิด, stress 61, merit 51) ส่วนผลที่รู้สึกชัดมีน้อย (wealth 29, favor 27, skill 16, career 11) — ตัวเลือกที่มีผลต่อทักษะมีแค่ 16 จาก 201 (8%) ทางแก้: เติมคู่ "ได้ X เสีย Y" ด้วยชนิดผลที่มีอยู่แล้ว (`wealth` `favor` `skill` `stress` ความเสี่ยงพลาด) ไล่จาก event ที่เจอบ่อยที่สุดก่อน; ข้อจำกัดของการตรวจ: ไม่ได้อ่านเนื้อหาแต่ละ event ว่าข้อแลกเปลี่ยนชัดหรือไม่

## ถัดไป

### 4. แนวการเล่นแต่ละยุค + หลอดยุคสมัย (ทำคู่กัน)
ข้อ "แนวการเล่นแต่ละยุค" เป็นร่มของข้อ 2–3 และงานศึกด้านล่าง · หลอดอย่างเดียวไม่พอ ต้องมีเนื้อหายุคใหม่รองรับ

- [ ] **แนวการเล่นแต่ละยุคยังไม่ต่างกัน (พบ 2026-11-02) — ผู้เล่นรุ่น 1 กับรุ่น 5 เจอวงจรเดียวกัน** — ตรวจแล้ว: เหตุการณ์ประวัติศาสตร์ 18 รายการใน `rules.json` (2310–2394) เป็น shock อย่างเดียว (ริบทรัพย์ ฆ่า เพิ่มความหนักใจ ถอดตำแหน่ง) และ `trigger` ของ event มีแค่ `ageRange` `estates` `office` `requires` ไม่มีเงื่อนไขปี ระบบราชการ แต่งงาน มรดก เทศกาล ทำงานเหมือนกันตลอด 2288–2400 ทำให้ไม่มีแรงดึงให้เล่นต่อหลังตัวละครแรกตาย ทางแก้: ให้แต่ละยุคมีสิ่งใหม่ที่เล่นต่างจริง เช่น event ถูกเกณฑ์ไปทัพ/เลื่อนยศจากศึก (ข้อ "เหตุการณ์บ้านเมืองหลังเสียกรุง" ด้านล่าง, ข้อบวช, ข้อราชการ), ชาวต่างชาติ/การค้า (ข้อชาวต่างชาติ), ข่าวเตือนก่อนเสียกรุง (P0 ด้านบน); ต้องเพิ่มเงื่อนไขปี/ยุคใน `requires` (ยังไม่มีชนิด `Condition` เกี่ยวกับปี — ตรวจก่อน) และควรกำหนดว่าแต่ละยุค (ปลายกรุงศรี → เสียกรุง/ข้าวยาก → ธนบุรี → ร.1 → ร.2–3 → ร.4) มี "ธีมการเล่น" อะไร ผูกกับหลอดยุคสมัยใน UI (ดู UI ด้านล่าง) ข้อจำกัดของการตรวจ: ไม่ได้อ่านเงื่อนไขของ event ใน `events.json` ทีละตัว อาจมีเงื่อนไขปีซ่อนอยู่ใน `requires`

- [ ] **หลอดยุคสมัย (Era Timeline Bar) — ให้ผู้เล่นเห็นว่าอยู่ตรงไหนของ 2288–2400 และมีอะไรรออยู่ (เสนอ 2026-11-02)** — เป้าหมายคือให้อยากเล่นต่อหลังตัวละครแรกตาย; แบ่งเป็นช่วงยุคที่มีชื่อ (ปลายกรุงศรี → เสียกรุง/ข้าวยาก → ธนบุรี → ร.1 → ร.2–3 → ร.4) ใช้เหตุการณ์ใน `history` ของ `rules.json` เป็นหมุดบนหลอด พร้อมคำใบ้ว่ายุคหน้ามีอะไร (ต้องไม่สปอยล์จนผู้เล่นรู้ล่วงหน้าเรื่องที่ควรเป็นเซอร์ไพรส์ เช่น เสียกรุง — ดูข้อข่าวเตือนล่วงหน้าใน P0); ทำคู่กับข้อ "แนวการเล่นแต่ละยุคยังไม่ต่างกัน" ด้านบน เพราะหลอดอย่างเดียวไม่มีเนื้อหาใหม่รองรับ จะเป็นแค่ตัวนับปี; ส่วนเล็กทำได้ก่อน (หลอด + หมุดจาก `history`), ส่วนใหญ่คือ event เฉพาะยุค; ใช้โครงเดียวกับ `eraConditions` ใน `views.ts` ได้ (คำนวณจากปี ไม่เก็บใน state)

### 5. ศึกสงคราม การเกณฑ์ทัพ และการบวช (รวมจากหลายข้อ)
ถูกเกณฑ์ไปทัพ เลื่อนยศจากศึก ถูกลงโทษ บวชหลบ · ทำร่วมกับ P0 และข้อ 4

- [ ] **เหตุการณ์บ้านเมืองหลังเสียกรุงเป็น shock ทั้งหมด** — ศึก 2328–2391 และผลัดแผ่นดิน 2352/2367/2394 (lore: `event.*` ร่างจากพงศาวดารรัชกาลที่ 1–3 ฉบับเจ้าพระยาทิพากรวงศ์ ซึ่งเรียบเรียงตั้งแต่ 2412 จึงเป็น `inferred` เกือบหมด) ฆ่าคนวัย 18–50 ตามความเสี่ยงที่เป็นตัวเลขเกม (พงศาวดารไม่มียอดตายฝ่ายไทย) ทำให้สิ้นสาย 2/20 seed จากเดิม 0; ยังไม่มี event ให้ผู้เล่นถูกเกณฑ์ไปทัพ เลื่อนยศจากศึก หรือถูกลงโทษเพราะคุมพลไม่ทัน; ผลัดแผ่นดิน 2367 ควรให้ "ข้าหลวงเดิม" ได้ดี; การกวาดล้าง 2325 ใช้โอกาส 30% ต่อตระกูลฝ่ายพระเจ้าตาก (หลักฐานว่าแคบ แต่ตัวเลขเป็นของเกม)

- [ ] **บวชยังไม่มีทางอยู่ในสมณเพศตลอดชีวิต** — ผู้เล่นบวชพรรษาเดียวแล้วสึก, ญาติผู้ชายบวชตอน 19; คนที่ไม่แต่งงานยังไม่ได้เป็นพระ และการบวชยังไม่คุ้มครองจากการเกณฑ์ (ยังไม่มีระบบเกณฑ์)

### 6. เส้นทางตัวละครหญิง (รวม 3 ข้อ)
ผู้เล่นหญิงตัวเลือกน้อย สามีไม่ก้าวหน้า — ออกแบบพร้อมกัน; ข้อ "แบ่งหน้าที่ตามเพศ" ต้องการ lore ก่อน

- [ ] **บทบาทและเกมเพลย์ของตัวละครหญิง** — ปัจจุบันเส้นทางชีวิตหลักเอียงไปทางตัวละครชาย (งานราชการ กรมกอง ออกศึก) ขณะที่ตัวละครหญิงตัวเลือกน้อย; ควรเพิ่มบทบาท อาชีพ และการตัดสินใจของสตรีที่ส่งผลต่อฐานะ การเงิน และเกียรติของตระกูล (เช่น การบริหารจัดการทรัพย์สินในเรือน การค้าขายตลาด การงานสำรับ/เครื่องหอม/งานฝีมือ และสายสัมพันธ์ฝ่ายใน)
- [ ] **การแบ่งหน้าที่ตามเพศให้ชัดเจนตามบริบทสังคมยุคกรุงศรี–ต้นรัตนโกสินทร์** — กำหนดบทบาทชาย/หญิงให้ตรงกับประวัติศาสตร์และธรรมเนียมจริง (ชาย: ราชการ ไพร่สม/ไพร่หลวง ภาระศึกสงคราม เข้าเวรเกณฑ์แรงงาน; หญิง: กุมอำนาจเศรษฐกิจในบ้าน ค้าขาย ดูแลคลังเรือน อบรมเลี้ยงดูลูก)
- [ ] **ความก้าวหน้าในราชการของสามี (กรณีเล่นตัวละครหญิง)** — เมื่อเล่นเป็นภรรยา สามีที่เป็นขุนนางไม่มีพัฒนาการหรือความก้าวหน้าในราชสำนัก; ต้องตรวจสอบและเชื่อมกับระบบราชการ (`career.ts`) ให้สามีเลื่อนยศตำแหน่ง ได้รับเบี้ยหวัดตามศักดินา หรือมีอีเวนต์ราชการ/ศึกสงครามที่ส่งผลต่อครอบครัว

### 7. ดราม่าในครัวเรือน
ให้เหตุผลทางอารมณ์ให้เล่นรุ่นถัดไป (ผู้สืบที่ไม่ได้เลือกน้อยใจ ฯลฯ)

- [ ] **ดราม่าและความสัมพันธ์ขัดแย้งภายในครัวเรือน (Family Drama & Domestic Friction)** — เพิ่มมิติความขัดแย้งระหว่างคนในบ้าน: ลูกที่ไม่ได้เลือกเป็นทายาทเกิดความน้อยใจ/แตกแยก/ตัดขาด, ข้อพิพาทเรื่องการแบ่งมรดกและซ่อนทรัพย์, ความตึงเครียดแม่ผัวลูกสะใภ้, และความริษยาระหว่างเมียหลวงกับเมียน้อย เพื่อให้เรือนมีชีวิตชีวาและมีอุปสรรคทางอารมณ์

### 8. ทักษะของ NPC เติบโต และถ่ายทอดวิชาในครัวเรือน (รวม 3 ข้อ)
`Item.teaches` ยังไม่มีโค้ดอ่าน — ถ้าไม่ทำใน "ถ่ายทอดวิชา" ให้ลบฟิลด์ทิ้ง

- [ ] **ระบบสกิลของ NPC และการพัฒนาตนเองตามอายุ** — ตัวละครที่ไม่ได้เล่น (คนในตระกูล/ลูกหลาน/คู่ครอง) ยังไม่มีการพัฒนาทักษะเองเมื่อเติบโตขึ้น; ควรอัปเกรดสกิลอัตโนมัติตามวัย โดยอิงจากความถนัด อุปนิสัย (trait/aptitude) หรือความสนใจส่วนตัว
- [ ] **ระบบถ่ายทอดวิชาในครัวเรือน (พ่อแม่สอนลูก)** — ลูกควรเรียนรู้และเพิ่มสกิลจากพ่อแม่ได้ โดยมีเงื่อนไขเพดานความรู้ (พ่อแม่สอนได้ไม่เกินระดับสกิลที่ตัวเองมี); เชื่อมโยงกับตำราประจำตระกูล (`Item.teaches`) ที่ยังไม่มีโค้ดอ่าน
- [ ] ฟิลด์ใน content ที่ยังไม่มีโค้ดอ่าน: `Item.teaches` (ตำราประจำตระกูล), `anatomy.vital`, `anatomy.root`

### 9. สมดุลที่ค้างจากรอบ 2026-11-01
ตอนนี้มี balance regression ใน `sim:check` แล้ว (ดูช่วงที่ยอมรับใน `src/simcheck.ts` ฟังก์ชัน `balanceCheck`) — แก้แล้วให้ปรับช่วงให้ตรง

- [ ] **สมดุลรอบ 2026-11-01 (วัดด้วยการเล่นอัตโนมัติ 30 seed เลือกตัวเลือกแรกเสมอ)** — แก้แล้ว: ผู้สืบที่เป็นผู้ใหญ่เข้ารับราชการได้ผ่าน `career.petition` (อายุ 21–55 ปีละ 15% ชายขุนนางเท่านั้น ได้ขั้นแรกของกรม) ผู้เล่นที่มีตำแหน่งช่วงหลัง 2370 จาก 4% เป็น 30–38%; ความหนักใจของผู้เล่นมีแหล่งแล้ว (`playerStress` ใน `lifeEvents.ts`: ญาติใกล้ชิดตายตามความรัก, เมียที่ไม่รัก `visitColdAt`, เหตุการณ์บ้านเมือง `balance.life.historyStress`) ค่าเฉลี่ย 0.07→0.16 ปีที่ ≥0.25 จาก 1%→20% `adult.heavy_heart` (เกณฑ์ 0.4) 0.3→3 ครั้งต่อเกม — ตัวเลขทุกตัวเป็นของเกม ยังไม่มีผลต่อร่างกาย/ป่วย; เทศกาลลอยโคมลด 0.6→0.45 และนิสัยอยู่นานขึ้น 6→10 ปี (event เทศกาล 81→71 ครั้งต่อเกม); ยังไม่ได้แก้: เงินตระกูลต่อหัวลดจากราว 160 เหลือราว 30 ตำลึงเพราะญาติเพิ่มเร็ว (เงินผู้เล่นเองนิ่ง 100–250 ไม่ใช่ปัญหา), สิ้นสายราว 7–13% (2–4 จาก 30 seed), ผู้เล่นแก่เกิน (อายุมัธยฐานตอนรับช่วง ~50) และตำแหน่งยังไม่มีการเกษียณ
