### 2. ผูกทักษะกับความก้าวหน้า และทำให้ผลมองเห็นได้
**ทำแล้วเป็นส่วนใหญ่ (2026-11-02):** ขั้นวิชาในสายของกรมเพิ่ม `favor` ทุกปี (`careerSkill` ใน career.ts, `skillTrack` ใน offices.json, `skillFavorPerTier` 0.025 ใน balance.json), แผงตัวละครและตัวเลือก "เลื่อนยศ" บอกผล และ `npm run sim:check -- 30 invest` จำลองผู้เล่นที่ฝึกวิชาต่อเนื่อง — วัดแล้ว: ผู้เล่นถึงขั้นขุนขึ้นไป (หลัง 2370) 6% → 28%, มีตำแหน่ง 28% → 37% ยังอยู่ในช่วงสมดุล จึงคง 0.025 ที่ยังไม่ทำ: ให้ทักษะพื้นฐานมีผลด้วย (เช่น literacy ของกรมราชบัณฑิตย์ — ตอนนี้เป็นแค่เงื่อนไขเข้ากรม) เพราะเพิ่มตัวเลขของเกมโดยไม่มีเหตุผลชัด; ผลของโหมด invest ยังพ่วงผลของวิชาอื่น (ความหนักใจและสิ้นสายลดลงจาก perk) ไม่ใช่ผลของข้อนี้อย่างเดียว; ยังไม่ได้ลองเล่นจริงในเบราว์เซอร์
ผู้เล่นฝึกวิชาแล้วต้องเห็นว่าขึ้นยศเร็วขึ้น · เสร็จเมื่อ: หน้าเลื่อนยศ/ตัวเลือกแสดงตัวช่วยจากทักษะ (+Y%) และ `sim:check` ยังอยู่ในช่วงสมดุล
**ตรวจ 2026-11-05:** เกณฑ์เสร็จส่วนแสดงผลบรรลุแล้ว — แผงตัวละครบอก "วิชา… ขั้น N ช่วยให้เป็นที่โปรดปรานขึ้น 2.5% ต่อปี" (`officeStatus` ใน career.ts) และตัวเลือกเลื่อนยศบอกว่าฝีมือด้านนั้นช่วย (`careerHint`); ในเบราว์เซอร์เห็นเฉพาะข้อความกรณียังไม่มีขั้นวิชา ("ฝึกวิชา…จะช่วยให้เลื่อนยศเร็วขึ้น") ที่เหลือของข้อนี้คืองานค้นตัวบทกฎหมายตราสามดวง (ข้อด้านล่าง) ซึ่งเป็นงานค้นล้วน

- [ ] **ถูกถอดจากราชการแล้วกลับเข้าได้ง่ายเกินไป (พบ 2026-11-03; แก้บางส่วนใน 0.2.1)** — เดิมถูกถอดแล้วยื่นเข้ากรมใหม่ได้ปีละ 15% ทันที ผู้เล่นทำเรื่องแย่ถูกลดสองรอบก็ได้กลับเข้า ตอนนี้ตั้ง `Character.disgrace` เมื่อถูกลดจนหลุดจากราชการ: ยื่นเองไม่ได้จนกว่าผู้ใหญ่ที่ฝากตัวไว้ (`patron`) กราบทูลขออภัย (`pardonChance` 0.25 ต่อปี) ผลัดแผ่นดิน หรือครบ `disgraceYears` 20 ปี — ตัวเลขเป็นของเกม `invented` ไม่มีหลักฐานใน lore; ค้นเว็บแล้วพบแค่ว่ากฎหมายตราสามดวงมีโทษลดศักดินา/ถอดยศ และกษัตริย์อภัยโทษตั้งกลับได้ (ข้อมูลรอง ไม่มีเลขมาตรา) ยังไม่พบข้อห้ามกลับเข้ารับราชการ; ยังไม่ได้ทำ: event ขออภัยโทษให้ผู้เล่นเลือกเอง (ตอนนี้อัตโนมัติ), โทษต่อพ่อ/ตระกูล (ลา ลูแบร์: พ่ออาจร่วมรับโทษลูก), ตรวจตัวบทพระอัยการตำแหน่งนาขุนนางจากแหล่งชั้นต้น; ยังไม่ได้ลองเล่นจริงในเบราว์เซอร์

### 3. ข้อแลกเปลี่ยน "ได้อย่างเสียอย่าง" ใน event
**ทำแล้วบางส่วน (2026-11-02) — วัดความถี่จาก sim 30 seed:** 18.5% ของ event เป็นผลผูกมิตรที่มีตัวเลือกเดียว และ 24% เป็นเทศกาลที่ตัวเลือกส่วนใหญ่ได้บุญฟรี → เพิ่มต้นทุนเงินให้ตัวเลือกบุญหลักของวันพระ/งานวัด/ลอยโคม (0.3–1.5 ตำลึง ตัวเลขของเกม), ผูกมิตรสำเร็จมีตัวเลือก "เลี้ยงฉลอง" (เสีย 1 ได้เพื่อนสนิทขึ้น) และผูกมิตรไม่สำเร็จมีตัวเลือก "ฝากขนมไปคุยอีกครั้ง"; ปุ่มแสดง "เสียเงิน X ตำลึง" ผ่าน `everydayHint` และมีเทสต์ใน `sim:check` ว่า event เหล่านี้มีทั้งตัวเลือกเสียเงินและไม่เสีย ที่ยังไม่ทำ: ตั้งชื่อลูก (`family.newborn`, รอ lore), event ที่เหลือนอกกลุ่มที่เจอบ่อยที่สุด, ต้นทุนเวลา/แรงงานในเรือน (ตอนนี้มีแค่เงินกับความหนักใจ); ยังไม่ได้ลองเล่นจริงในเบราว์เซอร์ และตัวเลขต้นทุนยังไม่ผ่านการเล่นจริง
**รอบ 2 (2026-11-05): [design-tradeoffs.md](design-tradeoffs.md)** — วัดใหม่จากผู้เล่นสุ่ม 30 seed (5 event แรกเกือบครึ่งของที่เจอ); คำใบ้บอก "ได้ฝึก{วิชา}" และ "ได้เงิน" แล้ว, ปรับวันพระ ลอยโคม รดน้ำผู้ใหญ่ (เพิ่มตัวเลือกไปวัดก่อน) ซ้อมมวย, `sim:check` มีตัวตรวจตัวเลือกแพ้ขาด (event ≥ 1%) **รอบ 3 (2026-11-05):** ตายร้าย "ฝังไว้ก่อน" มีค่าใช้จ่าย (เอาออกจากรายการยกเว้นแล้ว), เก็บบัว "ไม่ไป" ได้ฝึกงานบ้าน — ที่เหลือ: ตัวเลือก "ให้พระตั้งชื่อ" ไม่มีหลักฐาน (lore ว่าหมอดู/ผู้ใหญ่ตั้ง — รอผู้ใช้ตัดสิน ดู design-tradeoffs.md หัวข้อ 7), ต้นทุนเวลา/แรงงาน (ต้องมีระบบใหม่)
เสร็จเมื่อ: event ที่เจอบ่อยที่สุดมีตัวเลือกที่ได้-เสียชัดเจนอย่างน้อยหนึ่งคู่

- [ ] **event ส่วนใหญ่ยังไม่มีข้อแลกเปลี่ยน "ได้อย่างเสียอย่าง" ที่จับต้องได้ (เสนอ 2026-11-02)** — นับจากโครงสร้างข้อมูล: 71 event 201 ตัวเลือก มีแค่ 8 ตัวที่ไม่มี effect เลย แต่ผลส่วนใหญ่เป็นของเบา มองไม่เห็น (bond/relation 63 ครั้งต่อชนิด, stress 61, merit 51) ส่วนผลที่รู้สึกชัดมีน้อย (wealth 29, favor 27, skill 16, career 11) — ตัวเลือกที่มีผลต่อทักษะมีแค่ 16 จาก 201 (8%) ทางแก้: เติมคู่ "ได้ X เสีย Y" ด้วยชนิดผลที่มีอยู่แล้ว (`wealth` `favor` `skill` `stress` ความเสี่ยงพลาด) ไล่จาก event ที่เจอบ่อยที่สุดก่อน; ข้อจำกัดของการตรวจ: ไม่ได้อ่านเนื้อหาแต่ละ event ว่าข้อแลกเปลี่ยนชัดหรือไม่

- [ ] **ความเห็นผู้เล่น (ผู้ใช้ส่งต่อ 2026-11-05; ย้ายจาก BACKLOG 2026-11-05): "ลูกตายตลอด เล่นแล้วหดหู่ ควรมีหมอรักษาลูก และตัวเองป่วยง่ายตายตั้งแต่อายุน้อย"** — วัดแล้ว (ผู้เล่นสุ่ม 40 seed ทั้งสายตระกูล, สคริปต์ชั่วคราว): ลูกของผู้เล่น 300 คน ตายก่อน 1 ขวบ 17% · ก่อน 5 ขวบ 30% · ก่อน 15 ปี 40% (ไข้ทั่วไป 61 ไข้ทรพิษ 27 ศึก/ข้าวยาก/อหิวาต์ 12 จากที่ระบุสาเหตุได้); ผู้เล่นตอนผู้ใหญ่ 112 ชีวิต อายุตายมัธยฐาน 63 ตายก่อน 40 ปี 26% (ราวครึ่งเป็นเหตุการณ์ประวัติศาสตร์: เสียกรุง ถูกกวาดต้อน อหิวาต์) · เทียบหลักฐาน: ทารกตายของเกม (`balance.mortality.infant` 0.2) ใกล้ตัวเลขแรกที่มีจริง 234/1,000 ของกรุงเทพฯ ทศวรรษ 2473 (`health.children_dying_young`) และ "ไข้ทรพิษบางปีพาเด็กไปถึงหนึ่งในสาม" (`health.smallpox_endemic`) — ตัวเลขจึงไม่ได้สูงเกินหลักฐาน **ปัญหาจริงคือผู้เล่นทำอะไรไม่ได้**: ลูกตายด้วยลูกเต๋าทุก 1 ม.ค. (`mortalityYearTick`) ไม่มี event ไม่มีตัวเลือก ไม่มีหมอ (ต่างจากผู้เล่นเองที่มี `body.grave_illness` ให้เลือกตามหมอยา); ทางป้องกันที่มีอยู่ผู้เล่นมองไม่เห็นว่าช่วยลูก: มรดกสายวงศาคณาญาติขั้น 1 (ทารก/ใต้ 5 ขวบ ×0.75) ขั้น 2 (×0.9), วิชาตำรายาสมุนไพรประจำเรือน (`learning_2` คนในเรือน ×0.85), ปลูกฝีหลัง 2382; event เด็กเลี้ยงยากตั้งใจไม่เปลี่ยนร่างกายเด็ก · ข้อเสนอ: (ก) event "ลูกไข้หนัก" แบบเดียวกับ `body.grave_illness` — แปลงการตายด้วยไข้ของลูกส่วนหนึ่งเป็นการตัดสินใจ (ตามหมอยา เสียเงิน / ยาพื้นบ้าน / หมอขวัญ `psyche.khwan_doctor` / รอดูอาการ) โดยคงยอดตายรวมเท่าเดิมด้วยวิธีเดียวกับ `graveIllnessDiceShare` (ไม่ลดความสมจริง แต่ให้ผู้เล่นมีส่วน) ต้องหา lore หมอยารักษาเด็ก; (ข) บอกผลของมรดก/วิชาต่อชีวิตลูกให้ชัดในหน้าวิชา; (ค) ไม่แนะนำลดอัตราตายเด็กตรงๆ เพราะขัดหลักฐาน — ถ้าจะลดต้องตัดสินโดยผู้ใช้และจดเหตุผล · ข้อจำกัด: ลูกที่ถูกยุบออกจากเซฟก่อนสคริปต์เห็นวันตาย (21 คน) นับว่าตายวันที่หายไป

### 4. แนวการเล่นแต่ละยุค + หลอดยุคสมัย (ทำคู่กัน)
**(2026-11-05) ทำข้อนี้ให้เป็น "ชั้นยุค" ที่เป็นข้อมูล** (ช่วงปีของ event กติกา และกฎหมาย) เพราะ 4c ต้องใช้ตอนขยายเรื่องถึง 2484
**รอบ 1 เสร็จ (2026-11-05): [design-eras.md](design-eras.md)** — ยุค/สถาบันเป็นข้อมูลใน `rules.json`, เงื่อนไข `year`/`era`, lint ตามช่วงปี, shock กลางปี, event ยุคธนบุรี 2 ตัว (ข้าวแจก 2311–12, เลือกข้าง 2325) หลอดยุคมีอยู่แล้วตั้งแต่ก่อนหน้า · ที่เหลือ: event ยุค ร.1 ร.2–3 ร.4, หมุดเหตุการณ์บนหลอด, ความเร็วนาฬิกา (ผู้ใช้ให้คงไว้ก่อน)
ข้อ "แนวการเล่นแต่ละยุค" เป็นร่มของข้อ 2–3 และงานศึกด้านล่าง · หลอดอย่างเดียวไม่พอ ต้องมีเนื้อหายุคใหม่รองรับ

- [ ] **แนวการเล่นแต่ละยุคยังไม่ต่างกัน (พบ 2026-11-02) — ผู้เล่นรุ่น 1 กับรุ่น 5 เจอวงจรเดียวกัน** — ตรวจแล้ว: เหตุการณ์ประวัติศาสตร์ 18 รายการใน `rules.json` (2310–2394) เป็น shock อย่างเดียว (ริบทรัพย์ ฆ่า เพิ่มความหนักใจ ถอดตำแหน่ง) และ `trigger` ของ event มีแค่ `ageRange` `estates` `office` `requires` ไม่มีเงื่อนไขปี ระบบราชการ แต่งงาน มรดก เทศกาล ทำงานเหมือนกันตลอด 2288–2400 ทำให้ไม่มีแรงดึงให้เล่นต่อหลังตัวละครแรกตาย ทางแก้: ให้แต่ละยุคมีสิ่งใหม่ที่เล่นต่างจริง เช่น event ถูกเกณฑ์ไปทัพ/เลื่อนยศจากศึก (ข้อ "เหตุการณ์บ้านเมืองหลังเสียกรุง" ด้านล่าง, ข้อบวช, ข้อราชการ), ชาวต่างชาติ/การค้า (ข้อชาวต่างชาติ), ข่าวเตือนก่อนเสียกรุง (P0 ด้านบน); ต้องเพิ่มเงื่อนไขปี/ยุคใน `requires` (ยังไม่มีชนิด `Condition` เกี่ยวกับปี — ตรวจก่อน) และควรกำหนดว่าแต่ละยุค (ปลายกรุงศรี → เสียกรุง/ข้าวยาก → ธนบุรี → ร.1 → ร.2–3 → ร.4) มี "ธีมการเล่น" อะไร ผูกกับหลอดยุคสมัยใน UI (ดู UI ด้านล่าง) ข้อจำกัดของการตรวจ: ไม่ได้อ่านเงื่อนไขของ event ใน `events.json` ทีละตัว อาจมีเงื่อนไขปีซ่อนอยู่ใน `requires`

- [ ] **หลอดยุคสมัย (Era Timeline Bar) — ให้ผู้เล่นเห็นว่าอยู่ตรงไหนของ 2288–2400 และมีอะไรรออยู่ (เสนอ 2026-11-02)** — เป้าหมายคือให้อยากเล่นต่อหลังตัวละครแรกตาย; แบ่งเป็นช่วงยุคที่มีชื่อ (ปลายกรุงศรี → เสียกรุง/ข้าวยาก → ธนบุรี → ร.1 → ร.2–3 → ร.4) ใช้เหตุการณ์ใน `history` ของ `rules.json` เป็นหมุดบนหลอด พร้อมคำใบ้ว่ายุคหน้ามีอะไร (ต้องไม่สปอยล์จนผู้เล่นรู้ล่วงหน้าเรื่องที่ควรเป็นเซอร์ไพรส์ เช่น เสียกรุง — ดูข้อข่าวเตือนล่วงหน้าใน P0); ทำคู่กับข้อ "แนวการเล่นแต่ละยุคยังไม่ต่างกัน" ด้านบน เพราะหลอดอย่างเดียวไม่มีเนื้อหาใหม่รองรับ จะเป็นแค่ตัวนับปี; ส่วนเล็กทำได้ก่อน (หลอด + หมุดจาก `history`), ส่วนใหญ่คือ event เฉพาะยุค; ใช้โครงเดียวกับ `eraConditions` ใน `views.ts` ได้ (คำนวณจากปี ไม่เก็บใน state)

- [ ] **เกมจบเร็วเกินไป / อยาก "เลื่อนไทม์ไลน์" (ย้ายจาก BACKLOG 2026-11-04) (ความเห็นผู้เล่นหลังเล่น 2 วัน (ผู้ใช้ส่งต่อ 2026-11-04))** — ผู้เล่นว่าช่วงราว 120 ปีผ่านไปไวมาก กดความเร็วสูงสุดแป๊บเดียวจบ; ตัวเลขตอนนี้: `SPEED_DAYS_PER_SEC = [0, 3, 8, 20, 60, 180]` (`src/engine/engine.worker.ts`) — 2288→2400 ราว 40,900 วัน = ~4 นาทีที่ความเร็ว 5, ~11 นาทีที่ 4, ~34 นาทีที่ 3 (ไม่นับเวลาหยุดรอ event) ข้อควรถามผู้เล่นก่อน: "เลื่อนไทม์ไลน์" หมายถึง (ก) ทำให้เวลาเดินช้าลง/ลดความเร็วสูงสุด (ข) ขยายช่วงเวลาของเกม (`lore/config.json` gamePeriod 2275–2400, เริ่ม 2288) หรือ (ค) ให้แต่ละปีมีเรื่องให้ตัดสินใจมากขึ้นจนเวลาไม่ไหลผ่านเฉยๆ — ข้อ (ค) น่าจะตรงกับอีกสองข้อด้านล่าง; ข้อควรรู้: หลัง 2400 เล่นต่อเป็นเรื่องสมมติได้อยู่แล้ว — เข้าหมวดนี้เพราะทางแก้ (ค) คือเนื้อหาเฉพาะยุค ส่วน (ก) ปรับความเร็วเป็นงานเล็กทำแยกได้เมื่อผู้เล่นตอบ

### 4b. เมือง สายน้ำ การเดินทาง และโรคที่ลามตามเส้นทาง (เข้า PLAN 2026-11-05 ต่อจากข้อ 4)
**ร่างออกแบบ: [design-travel.md](design-travel.md)** — แผนที่ลำน้ำเจ้าพระยาอยุธยา–ปากน้ำ + ทางตะวันตก 10–15 จุด, เดินทางคิดผลทันที, ไข้ป่วง 2363 ลามตามแผนที่, ยังไม่มีแผนที่บนหน้าจอ · ลำดับงานในหัวข้อ 5 ของเอกสาร (ขั้น 0 ค้น lore ทำคู่ขนานได้)
ผู้เล่นรู้สึกว่าการเดินทางเป็นการตัดสินใจ และโรคระบาดมาจากที่ไหนสักแห่งแล้วใกล้เข้ามา · เสร็จเมื่อ (รอบแรก): ไข้ป่วง 2363 ถึงกรุงราว 15 วันหลังปล่อยและยอดตายอยู่ในช่วงเดิม, event หนีโรค/ไปดูแลพ่อแม่ต่างเมืองมีตัวเลือกเส้นทางที่ต่างกันจริง, `sim:policy` ผ่านประตูเดิม

- [ ] **แผนที่เมือง/สายน้ำ ความหนาแน่นประชากร การเดินทาง และโรคระบาดที่ลามตามเส้นทาง (เสนอ 2026-11-05 โดยผู้ใช้; ย้ายจาก BACKLOG 2026-11-05)** — ตั้งใจเป็นฐานของ "ตัวละครหลากหลายอาชีพและถิ่นกำเนิด" (เกี่ยวกับ PARKED หัวข้อ "เส้นเชลยศึกและตัวละครผู้เล่นอยู่ต่างที่"); เดินทางต้องเลือกเส้นทาง เช่น ผ่านเมืองที่มีโรคระบาด (เร็วแต่เสี่ยงติด) หรืออ้อม (ช้า/อันตรายกว่า) และการเดินทางของคนทำให้โรคลามไปด้วย ใช้แม่น้ำ/คลองเป็นเส้นทางหลักเพราะสมัยนั้นเดินทางด้วยเรือ · โมเดลที่น่าใช้: กราฟเมือง-เส้นทาง (เมือง = จุด มีประชากร/ความหนาแน่น; เส้นทาง = แม่น้ำ คลอง ทางบก มีระยะวัน ความเสี่ยง ฤดูน้ำ), เลือกเส้นทางด้วย Dijkstra/A* ที่ต้นทุน = เวลา + ความเสี่ยงที่ผู้เล่นให้น้ำหนัก, โรคระบาดแบบ metapopulation SIR (นับสัดส่วนป่วยต่อเมือง ไม่ใช่รายคน) ลามตามเส้นทางด้วยแรงดึงดูด (gravity model ตามประชากรสองเมือง/ระยะ) · ข้อจำกัด: lore สถานที่มีแค่ 3 ข้อ (`lore/entries/place.json`) ต้องค้นชื่อเมือง สายน้ำ ระยะเดินทางจากแหล่งชั้นต้นก่อน ตัวเลขประชากรรายเมืองแทบไม่มีหลักฐาน (ต้องเป็นตัวเลขของเกม), โรคระบาดตอนนี้เป็นสถานะทั้งเกมใน `meta.plague` (`events.ts`, `handover.ts`) ไม่มีระดับเมือง · ความเห็นแรก: เริ่มเล็ก ~10–15 จุดรอบกรุง และให้ผู้เล่นเห็นผลผ่าน event เดินทาง ก่อนทำโรคลามเต็มระบบ · **ร่างออกแบบ (2026-11-05): [docs/design-travel.md](design-travel.md)** ผู้ใช้ตัดสินครบ 5 ข้อแล้ว (หัวข้อ 7)

### 4c. อาชีพหลากหลาย เศรษฐกิจ เป้าหมายชีวิต และเรื่องอิงประวัติศาสตร์ถึง พ.ศ. 2484 (เข้า PLAN 2026-11-05 ต่อจาก 4b)
ทำหลังข้อ 4 (ชั้นยุค) และ 4b (เมือง/การเดินทาง) เพราะต้องใช้ทั้งสองอย่าง · ค้น lore ยุคหลัง 2400 ทำคู่ขนานได้ตั้งแต่ตอนนี้
ผู้เล่นรู้สึกว่าแต่ละยุคเล่นต่างกันจริง (แบบสี่แผ่นดิน) และเลือกทางชีวิตเองได้นอกจากราชการ

- [ ] **อาชีพเป็นข้อมูลทั่วไป** — อาชีพบอกแหล่งรายได้ วิชาที่ใช้ เมืองที่ทำได้ ฐานะ; ราชการเป็นอาชีพหนึ่ง แล้วเพิ่มพ่อค้า ช่าง ชาวนา · เสร็จเมื่อ: ผู้เล่นเลือก/เปลี่ยนอาชีพได้อย่างน้อย 2 แบบนอกราชการ และ `sim:check` สมดุลเงินยังอยู่ในช่วง
- [ ] **เศรษฐกิจอย่างง่าย** — ราคาข้าว/ของรายปีรายเมือง ผูกกับข้าวยาก น้ำท่วม และการค้าระหว่างเมือง · เสร็จเมื่อ: ปีข้าวแพงเห็นผลต่อรายได้/รายจ่ายของเรือนต่างกันตามอาชีพ
- [ ] **ความตั้งใจแบบเป้าหมายชีวิต** — ย้ายเรือน เปลี่ยนอาชีพ ส่งลูกไปเรียน เริ่มค้าขาย (ต่อยอด `intent.ts` ที่ตอนนี้มีแค่กับคน) · เสร็จเมื่อ: มีอย่างน้อย 2 เป้าหมายที่ใช้เวลาหลายปีและล้มเหลวได้
- [ ] **ข่าวเดินทางตามระยะ** — ข่าวศึก/โรคถึงเมืองไกลช้ากว่า ใช้แผนที่ของ 4b
- [ ] **ขยายเรื่องอิงประวัติศาสตร์ ขั้น 1 ถึงปลายรัชกาลที่ 5 (ราว 2453)** — ต้องลง lore ก่อน: เศรษฐกิจหลังสนธิสัญญาเบาว์ริง, การเลิกทาสและเกณฑ์ทหาร, ราชการแบบใหม่ ฯลฯ; กติกาเปลี่ยนตามยุคผ่านชั้นยุคของข้อ 4 (`servants.ts`, ศักดินาใน `career.ts`) · เสร็จเมื่อ: เล่นจาก 2288 ถึง 2453 ได้ `sim:check`/`sim:policy` ผ่าน และกติกาที่เลิกไปแล้วไม่ทำงานหลังปีนั้น
- [ ] **ขั้น 2 ถึง 2475** — นามสกุล (lint `naming.no_surname_pre_2456` ต้องผูกกับปี), ปฏิทินและการนับปีที่เปลี่ยน
- [ ] **ขั้น 3 ถึง 2484** — แล้วต่อด้วยโหมดเรื่องสมมติ (`fiction.ts`) ตามเดิม; ไม่ไปเลย 2484 ด้วยเรื่องอิงประวัติศาสตร์

- [ ] **โครงสร้างเบื้องหลังสำหรับเมือง/อาชีพหลากหลาย และขยายเรื่องอิงประวัติศาสตร์ถึงราว 2475–2489 (เสนอ 2026-11-05 โดยผู้ใช้; ย้ายจาก BACKLOG 2026-11-05; ผู้ใช้ถามถึง 2500 หรือหยุดก่อนสงครามโลกครั้งที่สอง ให้ได้ฟีลแบบสี่แผ่นดิน)** — ตรวจแล้ว: ไม่มีชั้น "ยุค" (event ไม่มีเงื่อนไขปี กติกาอย่างศักดินา ทาส ไม่มีนามสกุล ปฏิทินจันทรคติฝังอยู่ในโค้ดทั้งยุค), ไม่มีที่อยู่ (PLAN 4b), อาชีพมีแค่ราชการ 3 กรม (`Estate` มี merchant/foreigner แต่ไม่มีเกมเพลย์), เงินเป็นตัวเลขเดียวต่อคน รายได้มาจากศักดินา ทาส ที่นาเท่านั้น, ความตั้งใจของผู้เล่นมีแค่กับคน; lore 172 ข้อ ส่วนใหญ่ก่อน 2310 (138), 2310–2399 มี 31, หลัง 2400 มี 3 · ข้อเสนอเรียงลำดับ: (1) ชั้นยุคเป็นข้อมูล (ช่วงปีของ event/กติกา/กฎหมาย — ตรงกับ PLAN ข้อ 4) (2) ที่อยู่/เมือง (PLAN 4b) (3) อาชีพเป็นข้อมูลทั่วไป (แหล่งรายได้ วิชา ที่ตั้ง ฐานะ) แทนการผูกกับกรม (4) เศรษฐกิจอย่างง่าย: ราคาข้าว/ของรายปีรายเมือง (5) ความตั้งใจแบบเป้าหมายชีวิต (ย้ายเรือน เปลี่ยนอาชีพ ค้าขาย เรียน) (6) ข่าวเดินทางตามระยะ (7) ขยายปีเป็นขั้น · เรื่องขยายปี: 2400–2489 ระบบพื้นฐานเปลี่ยนเกือบทั้งหมด (ตัวอย่างที่รู้กันทั่วไป ต้องลง lore ก่อนใช้: สนธิสัญญาเบาว์ริง 2398, เลิกทาสและเกณฑ์ทหารแทนเกณฑ์ไพร่ ราว 2448, นามสกุล 2456, ปฏิวัติ 2475, สงครามโลกครั้งที่สอง 2484) แต่แหล่งข้อมูลยุคนี้หาง่ายกว่ายุคอยุธยามาก · ความเห็นแรก: ขยายทีละขั้น จบรัชกาลที่ 5 (2453) ก่อน แล้วค่อยไป 2475/2484; ไม่แนะนำเลย 2489 เพราะเข้าใกล้รัชสมัยปัจจุบัน ความอ่อนไหวทางการเมืองและกฎหมายสูง และเกมมีหลักพระมหากษัตริย์อยู่นอกฉากอยู่แล้ว · **ผู้ใช้ตัดสิน 2026-11-05: เรื่องอิงประวัติศาสตร์ไปถึง พ.ศ. 2484 (ก่อนสงครามโลกครั้งที่สอง) แบบเป็นขั้น** — ขั้นแรกถึงปลายรัชกาลที่ 5 (ราว 2453) แล้วค่อย 2475 → 2484; หลัง 2484 ใช้โหมดเรื่องสมมติ (`fiction.ts`) ต่อ; ต้องมีชั้นยุค (PLAN ข้อ 4) ก่อน

### 4d. ลักษณะที่ตกทอดจากพ่อแม่ และบอกตอนเลือกคู่ (เข้า PLAN 2026-11-05 — ทำหลัง 4c)
ต่อยอดจาก 3b: ลูกเลี้ยงยาก/ลูกดก/อายุยืนกลายเป็นสิ่งที่เดาได้ตั้งแต่ตอนเลือกคู่ผ่านคำชาวบ้าน · ต้องหา lore คำเรียกของคนในยุคก่อน · แตะระบบแต่งงานที่ PARKED พักไว้ ("ลึกอยู่แล้ว หยุดเพิ่มก่อน") — ข้อนี้เป็นข้อยกเว้นเพราะมีผู้เล่นบ่นเรื่องลูกตาย

- [ ] **ลักษณะที่ตกทอดจากพ่อแม่ + บอกตอนเลือกคู่ ทำคู่กับระบบรักษาที่ครอบคลุมขึ้น (เสนอ 2026-11-05 โดยผู้ใช้ ต่อจากความเห็นผู้เล่นเรื่องลูกตาย; ย้ายจาก BACKLOG 2026-11-05)** — ผู้ใช้ยกตัวอย่างเกมแนวเดียวกัน (CK3): ตอนเลือกคู่เห็นว่าลูกจะดกแค่ไหน และลูกมีโอกาสได้ลักษณะดี/ร้ายอะไรจากพ่อแม่ เช่น พ่อแม่ฉลาดลูกมีโอกาสฉลาดแต่เกิด พ่อแม่เลือดจางลูกมีโอกาสเป็น — เพิ่มการวางแผนและให้ผู้เล่นควบคุมได้มากขึ้น · ตรวจแล้ว (2026-11-05): ตกทอดอยู่ค่าเดียวคือ `constitution` (`inheritConstitution` ใน `factory.ts`: 0.5 × ค่าเฉลี่ยพ่อแม่ + สุ่ม) แสดงเป็นป้าย "ขี้โรค" เท่านั้น; นิสัย (`personality`) สุ่มตอนเกิดไม่ตกทอด (ซึมซับภายหลังจาก `socialLearning`); ไม่มีค่าความดก; หน้าเลือกคู่ (`MatchView.detail`) บอกแค่ถิ่น ระยะ ฐานะ ความสนิท ไม่บอกสุขภาพ · ข้อควรระวัง: (1) คนสมัยนั้นไม่รู้จักพันธุกรรมหรือโรคอย่างธาลัสซีเมีย — ถ้าจะบอกผู้เล่นต้องบอกผ่านสิ่งที่คนในยุครู้ได้ เช่น คำชาวบ้าน "บ้านนั้นลูกดก" "ตระกูลนี้อายุยืน" "ลูกบ้านนี้เลี้ยงยาก" ไม่บอกเป็นเปอร์เซ็นต์ (WRITING.md: ความเชื่อเล่าผ่านปากคน ไม่บอกผลที่ตัวละครไม่รู้) และต้องหา lore รองรับ; (2) ทำแบบกลไกของเกมเอง ไม่ลอกชื่อ/รายการลักษณะของ CK3; (3) PARKED หัวข้อ "ระบบครอบครัวและการแต่งงาน — ลึกอยู่แล้ว หยุดเพิ่มก่อน" พักไว้เพราะ "ไม่ใช่สิ่งที่ผู้เล่นบ่น" — ตอนนี้มีผู้เล่นบ่นเรื่องลูกตายแล้ว ตอนปั่นให้ชั่งกับข้อนั้น · ทำต่อจากข้อ 3b "ลูกไข้หนัก ตามหมอรักษาได้" (event ลูกไข้หนัก/หมอรักษา) — เมื่อลูกเลี้ยงยากเป็นสิ่งที่เดาได้ล่วงหน้าและรักษาได้ ผู้เล่นจะวางแผนได้ทั้งตอนเลือกคู่และตอนลูกป่วย

### 5. ศึกสงคราม การเกณฑ์ทัพ และการบวช (รวมจากหลายข้อ)
ถูกเกณฑ์ไปทัพ เลื่อนยศจากศึก ถูกลงโทษ บวชหลบ · ทำร่วมกับ P0 และข้อ 4
**เก้าทัพ 2328–2329 และท่าดินแดง 2329–2330 ทำครบ 7 ขั้นแล้ว (2026-11-04): [design-war-2328.md](design-war-2328.md)** — ผู้เล่นถูกเกณฑ์ ไปเอง/ส่งญาติ/ส่งบ่าว/จ่ายแทน/หลบ ตายได้จากตัวเลือกเท่านั้น; ที่เหลือในข้อ 5: ศึกอื่นหลัง 2330 (ทวาย 2336, ถลาง 2352, อนุวงศ์ 2369, อานาม 2376, เจาดก 2384, ตั้วเหี่ยฉะเชิงเทรา 2391) ใช้แม่แบบเดียวกันได้ (ดู SYSTEM-NOTES), กบฏเจ้าสามกรมยังไม่มี lore, และต้องตรวจปีของศึกในรายการ `history` ว่าเหลื่อมวันจริงแบบเก้าทัพหรือไม่

- [ ] **เหตุการณ์บ้านเมืองหลังเสียกรุงเป็น shock ทั้งหมด** — ศึก 2328–2391 และผลัดแผ่นดิน 2352/2367/2394 (lore: `event.*` ร่างจากพงศาวดารรัชกาลที่ 1–3 ฉบับเจ้าพระยาทิพากรวงศ์ ซึ่งเรียบเรียงตั้งแต่ 2412 จึงเป็น `inferred` เกือบหมด) ฆ่าคนวัย 18–50 ตามความเสี่ยงที่เป็นตัวเลขเกม (พงศาวดารไม่มียอดตายฝ่ายไทย) ทำให้สิ้นสาย 2/20 seed จากเดิม 0; ยังไม่มี event ให้ผู้เล่นถูกเกณฑ์ไปทัพ เลื่อนยศจากศึก หรือถูกลงโทษเพราะคุมพลไม่ทัน; ผลัดแผ่นดิน 2367 ควรให้ "ข้าหลวงเดิม" ได้ดี; การกวาดล้าง 2325 ใช้โอกาส 30% ต่อตระกูลฝ่ายพระเจ้าตาก (หลักฐานว่าแคบ แต่ตัวเลขเป็นของเกม)

- [ ] **ให้ตัวละครเข้าไปเกี่ยวกับเหตุการณ์ใหญ่ ไม่ใช่แค่อ่านข่าว (ย้ายจาก BACKLOG 2026-11-04) (ความเห็นผู้เล่นหลังเล่น 2 วัน (ผู้ใช้ส่งต่อ 2026-11-04))** — ผู้เล่นยกตัวอย่าง กบฏเจ้าสามกรม, สงครามเก้าทัพ, อานามสยามยุทธ; ตอนนี้ `public/content/rules.json` › `history` มีเหตุการณ์ 19 รายการ (เก้าทัพ 2328, ท่าดินแดง 2329, ทวาย 2336, ถลาง 2352, อนุวงศ์ 2369, อานาม 2376, เจาดก 2384, ตั้วเหี่ยฉะเชิงเทรา 2391 ฯลฯ) แต่เป็นข่าว/ภาพพงศาวดารเท่านั้น — มีแค่ศึก 2308–2310 ที่ผู้เล่นตัดสินใจและมีผลจริง (เตรียมศึก หมายเรียกพล หนีหรืออยู่ ล้อมกรุง); lore ที่มีแล้ว: `event.nine_armies_2328`, `event.annam_war_2376`; **กบฏเจ้าสามกรมยังไม่มีใน lore และไม่อยู่ในรายการ history** (เป็นเหตุการณ์ช่วงผลัดแผ่นดินปลายอยุธยา ต้องหาแหล่งและปีที่ถูกก่อน ห้ามใส่ปีจากความจำ); แนวทางที่น่าจะใช้ซ้ำได้: แม่แบบ event ศึก 2308–2310 (เรียกพล/ส่งคนไป/จ่ายแทน/ผลต่อความโปรดปราน) ปรับตามยุค และผูกกับยศ/กรมของผู้เล่น (ขุนนางในกรมที่เกี่ยวถูกเรียกใช้) — ระวัง ROADMAP หลักการข้อ 5 (กษัตริย์อยู่นอกฉาก) และ art/README ข้อ 6 (ไม่สร้างภาพเจ้านาย) โดยเฉพาะกบฏเจ้าสามกรมที่ตัวละครหลักเป็นเจ้านาย — ข้อนี้คือเสียงผู้เล่นที่ยืนยันข้อก่อนหน้า (shock ทั้งหมด) ทำรวมกันได้; ใหม่คือกบฏเจ้าสามกรมซึ่งอยู่ก่อนเสียกรุง

- [ ] **บวชยังไม่มีทางอยู่ในสมณเพศตลอดชีวิต** — ผู้เล่นบวชพรรษาเดียวแล้วสึก, ญาติผู้ชายบวชตอน 19; คนที่ไม่แต่งงานยังไม่ได้เป็นพระ และการบวชยังไม่คุ้มครองจากการเกณฑ์ (ยังไม่มีระบบเกณฑ์)

### 6. เส้นทางตัวละครหญิง (รวม 3 ข้อ)
ผู้เล่นหญิงตัวเลือกน้อย สามีไม่ก้าวหน้า — ออกแบบพร้อมกัน; ข้อ "แบ่งหน้าที่ตามเพศ" ต้องการ lore ก่อน

- [ ] **บทบาทและเกมเพลย์ของตัวละครหญิง** — ปัจจุบันเส้นทางชีวิตหลักเอียงไปทางตัวละครชาย (งานราชการ กรมกอง ออกศึก) ขณะที่ตัวละครหญิงตัวเลือกน้อย; ควรเพิ่มบทบาท อาชีพ และการตัดสินใจของสตรีที่ส่งผลต่อฐานะ การเงิน และเกียรติของตระกูล (เช่น การบริหารจัดการทรัพย์สินในเรือน การค้าขายตลาด การงานสำรับ/เครื่องหอม/งานฝีมือ และสายสัมพันธ์ฝ่ายใน)
- [ ] **การแบ่งหน้าที่ตามเพศให้ชัดเจนตามบริบทสังคมยุคกรุงศรี–ต้นรัตนโกสินทร์** — กำหนดบทบาทชาย/หญิงให้ตรงกับประวัติศาสตร์และธรรมเนียมจริง (ชาย: ราชการ ไพร่สม/ไพร่หลวง ภาระศึกสงคราม เข้าเวรเกณฑ์แรงงาน; หญิง: กุมอำนาจเศรษฐกิจในบ้าน ค้าขาย ดูแลคลังเรือน อบรมเลี้ยงดูลูก)
- [ ] **ความก้าวหน้าในราชการของสามี (กรณีเล่นตัวละครหญิง)** — เมื่อเล่นเป็นภรรยา สามีที่เป็นขุนนางไม่มีพัฒนาการหรือความก้าวหน้าในราชสำนัก; ต้องตรวจสอบและเชื่อมกับระบบราชการ (`career.ts`) ให้สามีเลื่อนยศตำแหน่ง ได้รับเบี้ยหวัดตามศักดินา หรือมีอีเวนต์ราชการ/ศึกสงครามที่ส่งผลต่อครอบครัว

### 7. ดราม่าในครัวเรือน

- [ ] **ฉากเล็กๆ บอกเมียเรื่องเลื่อนยศ (เสนอ 2026-11-02 โดยผู้ใช้)** — หลังรับยศใหม่ มีบทสนทนากับเมียที่สุ่มได้หลายแบบตามความสัมพันธ์ เช่น สามีแซวว่าต่อไปเรียกว่า "คุณหลวง" ไม่ได้แล้ว เมียตอบว่าได้เป็น "คุณพระ" แล้วนี่นะ, เมียวิ่งมาถามว่าคุณกลับมาแล้วหรือเจ้าคะ, เลี้ยงอาหารฉลอง; เกิดไม่บ่อย (ต้องเลื่อนยศ) จึงเป็นจังหวะรางวัลที่ทำให้ยศมีความหมาย ความเห็นของผม: ทำคุ้ม ไม่ต้องมีกลไกใหม่ — ต่อเป็น follow-up ของ `career.promotion` (เฉพาะผู้เล่นที่มีเมีย), แตกบทพูดตามความรัก (ใช้ความสัมพันธ์ affection/`opinion`) ขั้นยศ (`officeTier`) และฐานะเมีย (หลวง/น้อย), ใส่ข้อแลกเปลี่ยนตามหลัก PLAN ข้อ 3 (เลี้ยงฉลอง เสียเงิน ได้หน้า/ความผูกพัน ↔ กินกันเงียบๆ ฟรี), ขยายไปถึงตอนถูกลดยศ/ถูกลงโทษ (เมียปลอบ) และฝั่งผู้เล่นหญิงที่สามีได้ยศ (ผูกกับ PLAN ข้อ 6) ได้ ข้อควรรู้: คำเรียก "คุณหลวง/คุณพระ" และ "อวยยศ" ยังไม่ได้ตรวจว่าใช้ในช่วง 2288–2400 — ต้องเช็ก lore `vocab.pronouns_1680s` และ WRITING.md ก่อนใช้ในข้อความ (ถ้าไม่มีหลักฐานใช้คำที่มีหลักฐานแทน); ภาพประกอบฉากนี้ยังไม่มี (ใช้ภาพฉากเรือนเดิมถอยไปก่อนได้)
