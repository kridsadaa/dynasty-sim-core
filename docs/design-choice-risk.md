# ร่างออกแบบ: ทำให้การเลือกของผู้เล่นมีผลต่อความเป็นความตายนอกช่วงศึก

สถานะ: **2026-11-04 — ผู้ใช้สั่งใช้ค่าเริ่มต้นและลงมือ: ขั้น 1–4 ของหัวข้อ 7 (กลไก, นโยบายทดสอบ, ความเสี่ยงชั้น 1, ปรับ `playerAdultScale`) ทำแล้ว (ดูหัวข้อ 10–11); ชั้น 2–3 ยังไม่ทำ** · ที่มา: ผู้ใช้สังเกตว่า "จิ้มมั่วก็รอดถึงอายุ 70" · งานนี้ยังไม่อยู่ใน PLAN (ตามกฎ CLAUDE.md ข้อเสนอใหม่ลง BACKLOG ก่อน) · ตัวเลขทั้งหมดในเอกสารนี้เป็น **ค่าตั้งต้นที่ต้องปรับด้วย sim:check** และเป็นของเกม ไม่ใช่ข้อมูลประวัติศาสตร์

## 1. ปัญหา (วัดแล้ว)

จำลองตัวละครแรก (ชายขุนนางเกิด 2281) n=80 ต่อนโยบาย หยุดเมื่อตัวละครแรกตาย (สคริปต์ชั่วคราว ไม่ได้ commit):

| นโยบาย | รอดถึง 30 | รอดถึง 70 | ตายจากประวัติศาสตร์ | ตายจาก event ที่ผู้เล่นเลือก |
|---|---|---|---|---|
| รอบคอบ (`bury_most`, `east_all`, `pay`, `home`) | ~76% | ~25% | 31% | 0% |
| ประมาท (`none`, `stay`, `serve`, `wall`) | ~35% | ~13% | 61% | 0% |

- **ศึก 2308–2310 ทำงานตามที่ออกแบบ:** เลือกต่างกัน รอดต่างกันเท่าตัว
- **นอกศึก การเลือกไม่มีน้ำหนักต่อชีวิตเลย** — ตายด้วยลูกเต๋ารายปีตามอายุ/ร่างกาย (`balance.mortality`: ผู้ใหญ่ 0.8%/ปี หลัง 50 เท่าตัวทุก 8 ปี) ปรับได้แค่ `mortalityShield` ×0.85–0.9

สาเหตุในโค้ด (ตรวจแล้ว):
1. ตัวเลือกที่มี `risk` มี 35 ตัว (`riskChance` ใน `will.ts`) แต่ผลเมื่อ **พลาด (`fail`) เป็นแค่เสียเงิน/หน้า/ความหนักใจ ไม่มีตายสักตัวนอกศึก** — แม้แต่ `life.drowning.dive` (กระโดดช่วยคนตกน้ำ) พลาดแล้วก็แค่เครียด
2. `kill` ใน event (4 จุด) ใช้ได้เฉพาะ `ch.local` (คนนอกตระกูล) — ผู้เล่นฆ่าคนอื่นได้ แต่ไม่มีผลย้อนกลับถึงชีวิต; `scheme.assassin` (ปุ่ม "จ้างคนลอบฆ่า" ใน `interactions.ts`) พลาดแล้วแค่ `wealth −50, favor −0.5, prestige −3` ไม่มีล้างแค้น
3. `wound` (8 event) ไม่ฆ่า — วงจรบาดแผล (`body.ts`: bleeding → open → infected → festering → healing) จบที่แผลเป็น/เสียอวัยวะ ไม่มีตายจากติดเชื้อ
4. `stress` ไม่เพิ่มความเสี่ยงตาย
5. ตายแล้วมีผู้สืบรับต่อ (ตั้งใจ — เป้าหมายแผลคือให้เล่นต่อ) จึงไม่รู้สึกเสี่ยงสูญเสียเกม

## 2. เป้าหมายและหลักการ

**เป้าหมาย:** ผู้เล่นที่ตัดสินใจดีควรอยู่ยืนกว่าผู้เล่นที่ประมาท **นอกช่วงศึกด้วย** และเห็นเหตุผลย้อนหลังว่า "ตายเพราะเลือกอะไร"

หลักการ (ตัดสินใจเองไม่ต้องรอ):
1. **เตือนก่อนเสมอ** — ตัวเลือกที่ตายได้ต้องมี `hintKey` บอกว่า "เสี่ยงถึงตาย" ไม่ใช่ตายลอยๆ (กันความรู้สึกถูกลงโทษโดยไม่รู้ตัว — ปัญหาเดียวกับ P0 "ถูกบังคับให้ตายตอน 30")
2. **ทุกตัวเลือกเสี่ยงต้องมีทางเลือกปลอดภัยที่เสียอย่างอื่น** (เงิน บุญ ความโปรดปราน เวลา) — ความเสี่ยงต้องแลกกับผลตอบแทน
3. **ไม่เพิ่มความตายรวมของเกม** — ย้ายความเสี่ยงจากลูกเต๋าฐานมาเป็นความเสี่ยงที่ผูกกับการเลือก (หัวข้อ 4)
4. **ผู้เล่นรอบคอบต้องดีกว่าฐานเดิม ผู้เล่นประมาทต้องแย่กว่า** ส่วนผู้เล่นที่เลือกสุ่มควรได้ใกล้ค่าเดิม
5. **ไม่ลงโทษผู้สืบ** — มีผลเฉพาะตัวผู้เล่นปัจจุบัน (และคนในเรือนเท่าที่เหตุนั้นกระทบจริง เช่น โรคระบาด)
6. **ตัวเลขเป็น `invented`** — ไม่มี lore เรื่องอัตราตายจากการตัดสินใจ ห้ามอ้างหลักฐาน

## 3. กลไกใหม่ที่ต้องมี

- **`kill` + `allowKin` ใน `risk.fail.effects` มีอยู่แล้ว** (`war.levy.serve` ใช้อยู่) และ worker รองรับผู้เล่นตายจากตัวเลือก (`settleDeathNow` ใน `engine.worker.ts`) — ไม่ต้องสร้าง op ใหม่ ที่ขาดคือโอกาสตายชั้นที่สอง จึงเพิ่ม `chance` ให้ `kill` (ทำแล้ว) และตัวตรวจเนื้อหาใน `content.ts`
- **ความเสี่ยงสองชั้น:** `risk.base` (พลาดไหม — ใช้ของเดิม) × `kill.chance` ใน `risk.fail` (พลาดแล้วตายไหม — ใหม่ ตั้งต่ำ 2–8%) ทำให้แต่ละจุดเสี่ยงตายรวม ~1–3% ไม่ใช่กำปั้นใหญ่
- **ตัวคูณความเสี่ยงรายปีของผู้เล่น** (`playerAdultScale` ใน `balance.mortality`) ลดฐานลูกเต๋าของผู้เล่นลงเท่าที่ความเสี่ยงจากการเลือกเพิ่ม (หัวข้อ 4) — ใช้เฉพาะผู้เล่น NPC ไม่เปลี่ยน ตาราง demography ใน `sim:check` จึงไม่กระเทือน
- **ข้อความตาย:** `deathCause` เพิ่มชนิดที่ผูกกับการเลือก (เช่น `situation:combat`, `situation:drowning`, `situation:feud`, `situation:wound_fever`) แล้ว modal แจ้งการตาย (`deathNotice` ใน `views.ts`) บอกเหตุแบบเจาะจง

### ชั้น 3 — ทำให้มองเห็น

- `hintKey` ของทุกตัวเลือกที่ตายได้ขึ้นข้อความ "เสี่ยงถึงชีวิต" (ระดับคำ: น้อย/ปานกลาง/มาก ไม่โชว์ %)
- modal แจ้งการตายบอกเหตุเจาะจงตามหัวข้อ 3
- (ทีหลัง) หน้าตระกูลมีบรรทัด "เคยรอดตายมาแล้ว N ครั้ง" ให้ผู้เล่นรู้ว่าเสี่ยงมาแล้วเท่าไร

## 5. งบความเสี่ยง (ให้ตายรวมไม่เพิ่ม)

เป้า: ผู้เล่นที่เลือก **สุ่ม** มีเส้นรอดใกล้ของเดิม ผู้เล่นรอบคอบอยู่ยืนกว่า ประมาทอยู่สั้นกว่า

ขั้นตอนปรับ:
1. ใส่ความเสี่ยงชั้น 1 ด้วยค่าตั้งต้นในตารางข้างต้น
2. วัดด้วย `sim:check` ใหม่ (หัวข้อ 6) แล้วดูว่าผู้เล่นสุ่มรอดถึง 60/70 ต่ำกว่าเดิมเท่าไร
3. ปรับ `playerAdultScale` (เริ่ม 0.75) ลดลูกเต๋าฐานของผู้เล่นจนผู้เล่นสุ่มกลับมาใกล้เดิม
4. ถ้ารอบคอบ−ประมาทยังต่างน้อยกว่า 10 จุด (นอกศึก) ให้เพิ่มน้ำหนักความเสี่ยงของตัวเลือกประมาทก่อน อย่าไปเพิ่มลูกเต๋าฐาน

ข้อควรระวัง: ความเสี่ยงจากการเลือกกระจุกอยู่ช่วงอายุที่มี event (14–50) ส่วนลูกเต๋าฐานกระจายทั้งชีวิต จึงต้องดูเส้นอายุ ไม่ใช่แค่ค่าเฉลี่ย

## 6. ต้องมีเทสต์ (ใน `src/simcheck.ts`)

- เพิ่มโหมด/นโยบายการเล่นอัตโนมัติ 3 แบบ (รอบคอบ / ประมาท / สุ่ม) เป็นส่วนหนึ่งของ `balanceCheck` — ตอนนี้ `sim:check` เลือกตัวเลือกแรกเสมอ (ซึ่งเป็นกรณีเลวร้ายของศึกเท่านั้น และไม่ชนความเสี่ยงอื่น)
- เกณฑ์ผ่านที่เสนอ:
  - ผู้เล่นสุ่ม: ตัวชี้วัดตารางชีพเดิมทั้งหมดอยู่ในช่วง (`อายุ 50 แล้วอยู่ถึง 70` 25–50% ฯลฯ)
  - รอบคอบ − ประมาท รอดถึงอายุ 60 **นอกช่วงศึก** ≥ 10–15 จุด
  - สัดส่วนผู้เล่นที่ตายจากเหตุที่ตัวเลือกก่อ 10–25% ของการตายตอนผู้ใหญ่
  - ตายก่อน 30 (ไม่นับกรุงแตก) ยังไม่เกินเพดานเดิม 35%
  - ทุกตัวเลือกที่มี `die` ต้องมี `hintKey` และมีตัวเลือกปลอดภัยอย่างน้อย 1 ตัวใน event เดียวกัน (ตรวจใน `lore:check`/validator)
- ใช้ seed คงที่ n ≥ 60 ต่อนโยบาย (สคริปต์ชั่วคราวใช้ ~48 วินาที ต่อ 180 รอบ)

## 7. ลำดับลงมือที่เสนอ

1. **op `die` + deathCause ใหม่ + ข้อความ modal** (+ เทสต์ว่าตายผ่าน event แล้ว `playerDied` ออกจริง)
2. **นโยบายเล่น 3 แบบใน `sim:check`** (วัดก่อนแก้ จะได้เห็นฐาน)
3. ชั้น 1: 1a, 1b (ปรับ event เดิม), 1d (แผลติดเชื้อ + event หมอยา), 1e (ตัวคูณความหนักใจ)
4. ปรับ `playerAdultScale` ให้ผ่านเกณฑ์หัวข้อ 6
5. ชั้น 2: 2b (โรคระบาด — ใช้ของศึกเป็นต้นแบบ ได้ผลสูงสุดต่อต้นทุน) → 2a (ล้างแค้น) → 2d
6. ชั้น 3 ส่วนที่เหลือ + อัปเดต `docs/SYSTEM-NOTES.md`

แต่ละข้อจบด้วย `npx tsc --noEmit` และ `npm test` ตาม CLAUDE.md; ถ้าตั้งใจเปลี่ยนสมดุลให้ปรับช่วงใน `balanceCheck` แล้วจดเหตุผลใน PLAN

## 8. สิ่งที่ผู้ใช้ต้องตัดสิน

1. **ความรุนแรงที่ยอมรับ:** ตัวเลือกเสี่ยงหนึ่งจุดตายได้ราว 1–3% (ค่าเริ่มต้น) พอไหม หรืออยากให้บางจุด (ล้างแค้น, โรคระบาด) เสี่ยงสูงกว่านี้
2. **ตายเพราะเลือกผิดเป็นเรื่องรับได้ไหม** เมื่อมีผู้สืบรับต่อ — หรืออยากให้มีกลไกชดเชย เช่น ตายอย่างกล้าหาญแล้วได้ตำนาน/บุญตกทอดแก่ผู้สืบ (`legend.ts` มีระบบตำนานแล้ว)
3. **ล้างแค้น (2a):** ให้การลอบฆ่าที่สำเร็จมีผลสะท้อนกลับได้หรือไม่ (ปัจจุบันสำเร็จแล้วไม่มีผลอะไรต่อผู้เล่น) และทำเป็นระดับความเสี่ยงตายของผู้เล่นเอง หรือของคนในเรือนด้วย
4. **ปลูกฝี (2c):** ทำเป็นข้อแรก ๆ หรือรอจนตรวจ lore ว่าปีที่เริ่มสอดคล้องกับช่วงเกม
5. **เห็นความเสี่ยงแค่ไหน:** เป็นระดับคำ (น้อย/กลาง/มาก) ตามเสนอ หรืออยากให้ผู้เล่นเห็นตัวเลข
6. **ลำดับ:** ทำตามหัวข้อ 7 หรือสลับเอาโรคระบาด (2b) ก่อน เพราะต้นทุนถูกและสอดคล้องกับระบบศึกที่ผู้เล่นยอมรับแล้ว

## 11. ชั้น 1 ลงมือแล้ว (2026-11-04)

- **1b นำจับโจร** (`career.patrol_thief.lead`): พลาดแล้วตาย 5% (`situation:combat`) นอกจากแผลลึกเดิม — ทางปลอดภัย `lawful`/`bribe`; hint "…ถึงชีวิต"

## 9. ความเสี่ยงของแผนนี้

- **อ่านนโยบายจากชื่อ id:** ผลวัดในหัวข้อ 1 เดานโยบายรอบคอบ/ประมาทจากชื่อตัวเลือก ต้องสร้างนโยบายที่ตรวจแล้วจริงตอนทำเทสต์
- **ความรู้สึกถูกบังคับ:** ถ้าเพิ่มจุดตายมากไป ผู้เล่นจะเจอ "ตายเพราะเลือกอะไรไม่รู้" อีกรอบ — จึงเริ่มจากน้อยจุดและต้องมี hint
- **ตารางชีพ:** ลดลูกเต๋าเฉพาะผู้เล่นทำให้ผู้เล่นอยู่ต่างจาก NPC ในตระกูลได้ ตรวจว่า invariant/ตาราง demography ยังผ่านเพราะ NPC ไม่เปลี่ยน
- **วงจรบาดแผล:** เพิ่มความตายให้ `festering` กระทบทุกคน (NPC ด้วย) ถ้าไม่จำกัดเฉพาะผู้เล่น — ต้องตัดสินว่าจำกัดหรือไม่ (ค่าเริ่มต้นเสนอ: จำกัดเฉพาะผู้เล่น)
